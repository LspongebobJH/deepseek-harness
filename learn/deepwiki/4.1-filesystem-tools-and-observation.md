The DeepSeek Harness (DSH) filesystem architecture provides a unified, capability-based interface for interacting with the host filesystem. It separates low-level I/O mechanics from model-facing tools and security policies. The system is built around the `ctx.fs` capability seam, allowing for interchangeable backends (e.g., local, remote, or sandzoned) while maintaining a consistent toolset for agents [packages/fs/fs/src/index.ts1-25](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs/src/index.ts#L1-L25)

## 1. Filesystem Capability Seam (`ctx.fs`)

The core of the filesystem subsystem is the `FileSystem` abstract class, which defines the primitive operations required by the harness [packages/fs/fs/src/index.ts15-20](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs/src/index.ts#L15-L20)

### Key Primitives

- **`resolve(path, opts)`**: Converts a relative or absolute path into an `FsTarget`, which contains a stable `targetKey` (the realpath) and a `displayPath` [packages/fs/fs-local/src/fsio.ts106-112](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L106-L112) [packages/fs/fs-local/src/fsio.ts145-151](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L145-L151)
- **`stat` / `lstat`**: Returns metadata including an opaque `FsVersion` token derived from high-resolution identity and freshness metadata (`dev:ino:size:mtimeNs:ctimeNs`) [packages/fs/fs-local/src/fsio.ts74-77](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L74-L77)
- **`readText` / `streamText`**: Reads UTF-8 text. Large files are streamed to avoid memory exhaustion, rejecting binary data via NUL-byte sampling [packages/fs/fs-local/src/fsio.ts17-22](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L17-L22)
- **`writeText` / `editText`**: Atomic mutation operations that support optional "intents" (optimistic locking guards) [packages/fs/fs-local/src/index.ts170-176](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/index.ts#L170-L176)

## 2. Local Filesystem Implementation (`fs-local`)

The `LocalFileSystem` class implements the `FileSystem` seam for the host machine [packages/fs/fs-local/src/index.ts66-70](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/index.ts#L66-L70)

### Atomic Writes and Windows Safety

To ensure data integrity, writes are atomic:

1. A temporary file is created in a private staging directory sibling to the target [packages/fs/fs-local/src/fsio.ts4-5](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L4-L5)
2. On Windows, the target's DACL (security descriptor) is copied to the temp file to preserve permissions using `copyFileDaclWin32` [packages/fs/fs-local/src/fsio.ts15](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L15-L15)
3. The file is `fsync`'d and then atomically renamed (using `replaceFileWin32` on Windows) to the target path [packages/fs/fs-local/src/fsio.ts15](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/fsio.ts#L15-L15) [packages/fs/fs-local/README.md72-73](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/README.md?plain=1#L72-L73)

### Concurrency Control

The backend maintains a `locks` Map of `targetKey` to `Promise<unknown>`. All mutating operations (`writeText`, `editText`) for a specific file are queued via `withLock()` to ensure that the read-guard-write cycle is never interleaved [packages/fs/fs-local/src/index.ts79-80](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/index.ts#L79-L80) [packages/fs/fs-local/src/index.ts93-106](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/fs-local/src/index.ts#L93-L106)

## 5. Observation Policy & Attachments

The `fs-observation-policy` plugin implements optimistic concurrency control for the filesystem, working alongside durable attachment storage (`attachment-local`).

### The "Read-Before-Write" Invariant

By default, the harness enforces a policy where an agent must have "observed" (read) a file version before it is allowed to modify it [packages/fs/tool-fs/README.md40-41](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/tool-fs/README.md?plain=1#L40-L41)

1. **Observation**: When `read` succeeds, the tool emits an observation event [packages/fs/tool-fs/src/edit.ts139](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/tool-fs/src/edit.ts#L139-L139)
2. **Intent**: When `write` or `edit` is called, the tool requests an "intent" via `ctx.waterfall('fs/write-intent', ...)` [packages/fs/tool-fs/src/write.ts110](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/tool-fs/src/write.ts#L110-L110)
3. **Validation**: The policy plugin checks its internal cache. If the file has changed since the last observation, it returns a `replaceIfVersion` guard or throws `FS_NOT_OBSERVED` [packages/fs/tool-fs/README.md70-71](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/fs/tool-fs/README.md?plain=1#L70-L71)

### Durable Attachments (`attachment-local`)

Image attachments handled by `read_image` are stored securely and durably via `LocalAttachmentStore` rooted below `DSH_HOME` [packages/attachment/attachment-local/src/index.ts1-6](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/attachment/attachment-local/src/index.ts#L1-L6) They support automatic content-based identification, intrinsic dimension bounding, and downscaling policies to optimize model token consumption [packages/attachment/attachment-local/src/index.ts33-54](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/attachment/attachment-local/src/index.ts#L33-L54)
