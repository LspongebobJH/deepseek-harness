DeepSeek Harness (`dsh`) is built upon the **Cordis** plugin framework. In `dsh`, every component—from model adapters and tool registries to the agent loop itself—is a plugin that contributes services, events, and effects to a shared context [docs/architecture.md9-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L9-L13). This architecture ensures that no part of the system is a privileged core; everything is replaceable via configuration [docs/architecture.md11-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L11-L13).

To ensure stability, auditability, and the ability to apply custom fixes, `dsh` **vendors** the Cordis framework and its foundation libraries into the `@deepseek-ai` scope [vendor/README.md1-5](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L1-L5).

Sources: [docs/architecture.md9-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L9-L13), [vendor/README.md1-5](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L1-L5)

### 1.2 Local Modifications

Significant hardening has been applied to the upstream source to support the complex lifecycle of autonomous agents:

- **Fiber Lifecycle Hardening**: Fixed reentrant disposal gaps in `vendor/cordis/src/fiber.ts`. An effect's owner-list wrapper is registered before its setup body runs, synchronous setup failure removes the wrapper, and async cleanup stays owner-visible until quiescence. Effect creation is rejected while the owner is `UNLOADING`, preventing cleanup-time registrations from escaping the unload snapshot. Child fibers register and receive their parent-owned disposer before `internal/plugin` publication, resolve dependency declarations added by that notification before activation, drain effects attached while pending, skip plugin execution when reentrant disposal invalidates the load epoch before its first checkpoint, and contain teardown-notification failures per observer `[vendor/README.md:38]`, [vendor/cordis/src/fiber.ts1-50](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/cordis/src/fiber.ts#L1-L50).
- **Loader Improvements**: `Fiber.update()` was modified to return its `internal/update` waterfall result, allowing Loader callers to await a restart while preserving synchronous config validation [vendor/README.md38](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L38-L38).
- **`package.json` Regeneration**: All `package.json` files were regenerated to add scoped names, release versions, publication metadata, precise bundled-runtime and declaration files, source exports, and workspace protocol dependencies [vendor/README.md34](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L34-L34).
- **`tsconfig.json` Regeneration**: All `tsconfig.json` files were regenerated to extend the repo-root `tsconfig.base.json`, emit TypeScript intermediates to `lib/types`, and declare project references [vendor/README.md35](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L35-L35).
- **TypeScript Internal Specifiers**: Local relative imports/exports in vendored TypeScript source were changed to explicit `.ts` specifiers to ensure correct emitted JS (`.js`) while declarations keep NodeNext-safe `.ts` specifiers [vendor/README.md36](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L36-L36).
- **`tsdown.config.ts`**: `schemastery/tsdown.config.ts` and `logger-console/tsdown.config.ts` are local files for per-package build-shape overrides (dual ESM+CJS output; separate node/browser entries) [vendor/README.md37](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/README.md?plain=1#L37-L37).

## 2. Plugin Lifecycle & Fiber Disposal

Cordis operates on a **Fiber** (`vendor/cordis/src/fiber.ts`) based system. Every plugin instance is a fiber that manages its own resources and effects.

Sources: [vendor/cordis/src/fiber.ts1-50](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/cordis/src/fiber.ts#L1-L50)

### 2.1 Service Injection & Context

Plugins interact via a `Context` (`vendor/cordis/src/context.ts`) object. Services (`vendor/cordis/src/service.ts`) are registered on this context and can be injected into other plugins using `ctx.inject` or by declaring them as dependencies.

- **Declaration Merging**: Services are added to the `Context` interface via TypeScript declaration merging. For example, `packages/core/agent-loop` merges the `agentLoop` key into the `Context` interface [packages/bundle/base/cordis.patch.yml67-69](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/bundle/base/cordis.patch.yml#L67-L69). The `dshHomePath` resolver is also merged into the `Context` for use in Loader `!!js` config expressions [packages/boot/app-boot/src/index.ts23-28](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/boot/app-boot/src/index.ts#L23-L28).
- **Reversible Effects**: Registrations (like events or services) are "effects" managed by `vendor/cordis/src/reflect.ts` that are automatically unwound when the plugin's fiber is disposed [docs/architecture.md13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L13-L13).

Sources: `[vendor/cordis/src/context.ts:1-40]`, `[vendor/cordis/src/service.ts:1-40]`, `[vendor/cordis/src/reflect.ts:1-30]`, `[packages/boot/app-boot/src/index.ts:23-28]`, [docs/architecture.md9-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L9-L13)

## 4. Event Bus & Waterfalls

Cordis provides a typed event bus via `EventsService` (`vendor/cordis/src/events.ts`). `dsh` categorizes these into three domains [docs/event-producer-consumer.md8-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L8-L32):

1. **Session Events**: Durable facts (e.g., `agent/created`, `agent/disposed`) appended to the log [docs/event-producer-consumer.md12-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L12-L13).
2. **Agent Events**: Live lifecycle hooks (e.g., `agent/pre-step`, `agent/status`) [docs/event-producer-consumer.md18-22](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L18-L22).
3. **Capability Events**: Policy and adapter attachments (e.g., `llm/stream`, `fs/*`) [docs/event-producer-consumer.md33-40](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L33-L40).

Sources: `[vendor/cordis/src/events.ts:1-60]`, [docs/event-producer-consumer.md8-40](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L8-L40)

### 4.1 Waterfall Mechanics

Events like `agent/pre-step` or `agent/request` are **waterfalls**. Listeners receive a `next` callback and must call it to allow the chain to continue. This pattern is used for intercepting and modifying model requests or injecting context [docs/event-producer-consumer.md18-20](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L18-L20).

## 5. Configuration & Bootstrapping

The `loader` plugin (`vendor/loader/src/index.ts`) manages the assembly of the plugin tree at boot. It uses `cordis.yml` to define the tree structure and provides the `Config` interface for each plugin [docs/config-catalog.md6-10](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/config-catalog.md?plain=1#L6-L10).

- **Plugin Config Catalog**: Every harness package declares a `Config` interface validated using `schemastery` (`@deepseek-ai/schemastery`) [docs/config-catalog.md19-28](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/config-catalog.md?plain=1#L19-L28).
- **Service Requirements**: Plugins declare dependencies via requirements declarations [packages/bundle/base/package.json41](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/bundle/base/package.json#L41-L41).
- **Isolate Realm**: Managed via `vendor/loader/src/config/group.ts` and `vendor/loader/src/config/entry.ts` to ensure certain services are isolated to specific agent instances [vendor/loader/src/config/entry.ts1-30](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/vendor/loader/src/config/entry.ts#L1-L30).
- **`!!js` Expressions**: Configuration files like `cordis.patch.yml` can contain `!!js` expressions evaluated by the loader against the `Context` (`vendor/cordis/src/context.ts`) to dynamically configure plugins `[packages/bundle/web-app/cordis.patch.yml:119-121]`, [apps/cli/tests/windows-shell.spec.ts28-33](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/apps/cli/tests/windows-shell.spec.ts#L28-L33).
