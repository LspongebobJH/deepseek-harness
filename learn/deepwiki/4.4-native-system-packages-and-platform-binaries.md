The native system packages sub-workspace contains low-level platform integration layers, process launchers, native addons (such as Win32 Job Object containment and FFI bindings), system dialog providers, and release pack/publish pipelines. These packages bridge Node.js execution environments with operating system primitives across Linux and Windows architectures, and define the independent release sequences.

---

## 1. Sub-Workspace Overview & Architectural Scope

The native system and subprocess sub-workspace is divided into core library families and release orchestration pipelines:

- **`@deepseek-ai/dsh-subprocess-local`**: Manages platform-specific subprocess bootstrapping, one-shot Linux `execve` runners, and Windows Job-owning runners [packages/subprocess/subprocess-local/src/spawn-runner.ts1-221](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn-runner.ts#L1-L221)
- **`@deepseek-ai/dsh-win32-process`**: Provides Koffi-based FFI bindings to native Windows APIs (`kernel32.dll`, `advapi32.dll`) for process creation, restricted tokens, anonymous pipes, and Job Object lifecycle management [packages/subprocess/win32-process/src/process.ts1-208](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/win32-process/src/process.ts#L1-L208)
- **`@deepseek-ai/dsh-directory-picker-native`**: Implements native Win32 folder selection dialogs via isolated worker threads and window-close fallback services [packages/host/directory-picker-native/tests/win32-dialog.spec.ts1-159](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/host/directory-picker-native/tests/win32-dialog.spec.ts#L1-L159)
- **Release and Packaging Scripts**: Governs independent release sequences (`dsh`, `vendor`, and `native/system/packages/*`) via families discovery, tarball payload validation, and immutable publishing gates [scripts/release/families.ts1-164](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/scripts/release/families.ts#L1-L164)

## 2. Windows Job Objects & Native FFI Bindings

Windows process containment relies on Job Objects to ensure that subprocess trees are cleaned up when parent processes terminate or disconnect. The `@deepseek-ai/dsh-win32-process` package exports Koffi binding tables to interact with Win32 APIs without requiring native compilation steps during installation.

### Process Spawning & Job Allocation

The function `launchWindowsJob()` initiates a runner process configured with a private IPC channel and file descriptors for redirected streams [packages/subprocess/subprocess-local/src/windows-job.ts124-188](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/windows-job.ts#L124-L188) The native binding table defined in `process.ts` implements `spawnPipedProcess()` and ordinary process creation via `CreateProcessW` / `CreateProcessAsUserW` [packages/subprocess/win32-process/src/process.ts171-200](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/win32-process/src/process.ts#L171-L200)

Sources: `packages/subprocess/subprocess-local/src/windows-job.ts:124-188`, `packages/subprocess/win32-process/src/process.ts:171-200`

## 3. Subprocess Runner Bootstrap & IPC Protocol

The runner infrastructure supports two distinct bootstrap mechanisms: a one-shot Linux `execve` bootstrap and a Windows Job-owning runner.

### Runner Launcher & Invocation Resolution

`runner-launch.ts` resolves the appropriate executable invocation based on whether the runtime is executing from source, built distribution, or a packaged binary [packages/subprocess/subprocess-local/src/runner-launch.ts27-40](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/runner-launch.ts#L27-L40)

The environment builder `runnerEnvironment()` strips control prefixes (`NODE_`, `TSX_`) and sets the `DSH_SUBPROCESS_RUNNER` selector variable before passing configuration to the child process [packages/subprocess/subprocess-local/src/runner-launch.ts66-84](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/runner-launch.ts#L66-L84)

## 4. Native Host Dialogs & Worker Threads

The `@deepseek-ai/dsh-directory-picker-native` package handles native OS folder selection dialogs on Windows via a worker thread architecture.

### Dialog Lifecycles and Abort Handling

`pickWin32Directory()` accepts an `AbortSignal` and manages worker communication [packages/host/directory-picker-native/tests/win32-dialog.spec.ts67-159](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/host/directory-picker-native/tests/win32-dialog.spec.ts#L67-L159) If an abort signal is triggered while the dialog is active, the host invokes a cleanup service using `WM_CLOSE` message dispatch against the thread ID reported by the worker, falling back to process termination (`worker.kill()`) if the dialog remains unresponsive [packages/host/directory-picker-native/tests/win32-dialog.spec.ts116-159](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/host/directory-picker-native/tests/win32-dialog.spec.ts#L116-L159)
