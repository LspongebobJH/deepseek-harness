Subagent orchestration in DeepSeek Harness (`dsh`) is managed through a dedicated capability seam that allows a parent agent to delegate tasks to child agents. This system abstracts the underlying transport (in-process, forked, or out-of-process via ACP, Codex, Claude Code, and DSH SDK) while providing a unified interface for lifecycle management, policy inheritance, and result reporting [packages/subagent/subagent/src/index.ts1-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/index.ts#L1-L32)

## Overview of the Subagent Seam

The `SubagentRuntime` service, registered under `ctx.subagents`, acts as a named-provider registry [packages/subagent/subagent/src/index.ts1-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/index.ts#L1-L32) It handles the transition from a model's intent to delegate (via tools) to the actual execution of a child agent.

### Key Delegation Modes

| Mode | Lifecycle | Ownership |
| --- | --- | --- |
| **One-shot** | Runs for a single turn and returns a final result. | Owned by the caller via a `SubagentRun` handle [packages/subagent/subagent/src/index.ts90](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/index.ts#L90-L90) |
| **Continuable** | Establishes a durable session that persists across multiple turns. | Managed by the `SubagentContinuationManager` [packages/subagent/subagent/src/index.ts67](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/index.ts#L67-L67) |

## Subagent Providers

Providers implement the `SubagentProvider` interface and register themselves with a unique name. They advertise their capabilities (e.g., `outputSchema`, `depthLimit`) which the runtime validates before dispatching a request [packages/subagent/subagent/src/types.ts86-92](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/types.ts#L86-L92)

### Provider Types

1. **In-Process (`spawn`/`fork`)**: Runs the child agent within the same Node.js process using the local `AgentLoop`.
   - `spawn`: A fresh agent context [packages/subagent/subagent/tests/continuation.spec.ts95](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/tests/continuation.spec.ts#L95-L95)
   - `fork`: Inherits the parent's completed turns [packages/subagent/subagent/tests/continuation.spec.ts96](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/tests/continuation.spec.ts#L96-L96)
2. **Agent Client Protocol (ACP)**: Spawns an external process that communicates via the ACP JSON-RPC protocol over stdio [packages/subagent/subagent-acp/tests/subagent-acp.spec.ts19-26](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-acp/tests/subagent-acp.spec.ts#L19-L26)
   - Implements a cooperative teardown ladder: EOF grace -> `SIGTERM` -> `SIGKILL` [packages/subagent/subagent-acp/src/run.ts82-86](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-acp/src/run.ts#L82-L86)
   - Handles unattended permission decisions via `PermissionPolicy` ('allow' | 'reject') [packages/subagent/subagent-acp/src/run.ts27](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-acp/src/run.ts#L27-L27)
3. **Product Drivers**:
   - **Claude Code**: Wraps the official `@anthropic-ai/claude-agent-sdk`. It manages a `ManagedClaudeCodeProcess` and maps SDK results to `SubagentResult` [packages/subagent/subagent-claude-code/src/run.ts39-41](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-claude-code/src/run.ts#L39-L41) [packages/subagent/subagent-claude-code/src/run.ts191-201](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-claude-code/src/run.ts#L191-L201)
   - **Codex**: Spawns the `codex app-server --stdio` child. Uses `CodexAppServerWire` to handle the JSON-RPC line transport [packages/subagent/subagent-codex/src/run.ts30-33](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-codex/src/run.ts#L30-L33) [packages/subagent/subagent-codex/src/run.ts135-137](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent-codex/src/run.ts#L135-L137)

## Continuable Subagents

Continuable subagents are designed for long-running interactions where the parent and child can exchange multiple messages over time.

### The Continuation Manager

The `SubagentContinuationManager` (internal to `SubagentRuntime`) tracks the residency of continuable children [packages/subagent/subagent/src/continuation.ts1-20](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/continuation.ts#L1-L20)

- **Activation**: A process-local residency epoch for a child agent. It stays resident while descendants it created are still running [packages/subagent/subagent/src/continuation.ts7-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/continuation.ts#L7-L13)
- **Cold Resume**: If a child is not resident, the manager reconstructs it from the persisted session log when a new message arrives [packages/subagent/subagent/src/continuation.ts151-152](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/continuation.ts#L151-L152)
- **Adjacent Messaging**: Agents can use `sendMessage()` to communicate with direct continuable children or parents [packages/subagent/subagent/README.md49-51](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/README.md?plain=1#L49-L51)

### Communication Mechanism

- **`followup`**: The parent sends a message to the child.
- **`reportFrom`**: The child sends a message back to the parent.
- **`SubagentSettledMessageSource`**: Durable attribution for the runtime's account of a child settling [packages/subagent/subagent/src/continuation.ts73-81](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/continuation.ts#L73-L81)

## Policy Inheritance and Depth Control

To prevent infinite recursion and ensure security, subagents inherit policies from their parents.

### Delegation Depth

The system tracks depth by inspecting the session lineage.

- `assertSubagentMaxDepth`: Throws a `SubagentDepthError` if the child would exceed the configured `maxDepth` [packages/subagent/subagent/src/depth.ts51](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/depth.ts#L51-L51) [packages/subagent/subagent/src/child-agent.ts118-120](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/child-agent.ts#L118-L120)

### Policy Composition

The function `applyChildComposition` is used for in-process agents to merge the parent's preset composition with the child's specific overrides [packages/subagent/subagent/src/child-agent.ts113-114](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subagent/subagent/src/child-agent.ts#L113-L114)
