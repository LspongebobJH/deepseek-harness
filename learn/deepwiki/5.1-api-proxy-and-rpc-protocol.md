The API Proxy system serves as the unified communication gateway between the DeepSeek Harness (`dsh`) host (Node.js) and its clients (Browser/Web UI or In-Process). It defines a type-safe RPC protocol using a structured message model, handles SSE/WebSocket/multiplexed streaming, and enforces strict schema validation and browser trust boundaries.

## System Architecture & Trust Boundary

The architecture decouples the logical API contract from the physical transport carrier. The `HostConnectionService` (in `client-connection`) implements business logic, exact `GET`/`HEAD`/`POST` route registries, and trust boundaries on the host [packages/client/connection/README.md28-35](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/README.md?plain=1#L28-L35) while the `ClientRemoteService` and `TypertGateway` manage client-side invocation [packages/api/gateway/src/client/index.ts142-183](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/gateway/src/client/index.ts#L142-L183)

### Browser Request Trust & Authentication

Every Host RPC method and WebSocket stream requires a valid browser session secured via a signed cookie and request trust checks in `assertTrustedAuthority` [packages/client/connection/src/api-request-trust.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/src/api-request-trust.ts) and `BrowserAuth` [packages/client/connection/src/browser-auth.ts](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/src/browser-auth.ts)

### RPC Method Domains & Transport

The Typert Gateway dispatches unary calls via POST and streams via multiplexed channels:

- **Unary Calls**: Executed over standard HTTP POST requests against `/api` routes handled by `bridge` [packages/client/connection/src/index.ts139-154](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/src/index.ts#L139-L154)
- **Streaming Transport**: Managed by `RemoteStreamMuxClient` or direct WebSocket channels (`/api/remote.mux`) [packages/api/gateway/src/client/index.ts142-183](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/gateway/src/client/index.ts#L142-L183)

## Streaming & Event Muxing

Real-time telemetry and session synchronization use dedicated stream controllers.

### Connection Generations & Recovery

The `ConnectionController` tracks generation readiness. The Host sends an initial `{ type: 'ready', clientId, host: { home } }` frame before emitting events [packages/client/connection/README.md45-53](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/README.md?plain=1#L45-L53) If connection drops, exponential backoff with jitter is applied [packages/client/connection/README.md45-53](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/README.md?plain=1#L45-L53)

## Schema Validation & Session Export Endpoint

Payloads crossing the wire and requests hitting the `/api` boundary undergo strict schema validation via `@deepseek-ai/schemastery` [packages/client/connection/src/index.ts3-10](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/src/index.ts#L3-L10) and body size bounds (default 300 MiB limit via `maxRequestBodyBytes`) [packages/client/connection/src/index.ts86-110](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/src/index.ts#L86-L110) Non-JSON responses like session logs and file exports are handled through dedicated exact routes [packages/client/connection/README.md28-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/connection/README.md?plain=1#L28-L32)
