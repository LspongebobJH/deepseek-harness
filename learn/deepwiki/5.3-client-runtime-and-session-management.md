The browser-side client runtime provides the core orchestration layer for DeepSeek Harness (`dsh`), managing session states, workspaces, history pagination, gap repair, multiplexed stream dispatch, and client-side module loading with Hot Module Replacement (HMR). Built on the Cordis service injection framework, it decouples raw session events from React UI rendering through structured snapshot projections.

## Overview & Service Architecture

The runtime exposes its core capabilities through Cordis service declarations into the browser execution context via `ctx.sessions` and `ctx.workspaces` [packages/client/runtime/src/client/index.ts1-13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/index.ts#L1-L13) It maintains an object hierarchy that mirrors host state independently of UI components.

### Primary Runtime Services

- **`SessionRuntime`**: The root service governing the session list mirror, `SessionManager`, and client-side mirrors of the Agent scope tree [packages/client/runtime/src/client/sessions/service.ts1-40](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/service.ts#L1-L40)
- **`SessionManager`**: Multiplexes incoming host frames (`MuxFrame`) and routes them to target `Session` instances based on `SessionId` [packages/client/runtime/src/client/sessions/manager.ts100-140](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/manager.ts#L100-L140)
- **`Session`**: Represents a single conversation thread, maintaining an in-memory event window, history paging state, and projection caches [packages/client/runtime/src/client/sessions/session.ts1-150](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/session.ts#L1-L150)
- **`ConversationNodeAssembler`**: The event-folding engine translating raw `SessionEvent` records into structured conversation nodes consumed by chat views [packages/client/runtime/src/client/sessions/conversation-assembler.ts1-50](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/conversation-assembler.ts#L1-L50)
- **`WorkspaceRuntime`**: Manages filesystem contexts, binds workspaces to session threads, and supports blank session reuse [packages/client/runtime/src/client/workspaces/service.ts50-116](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/workspaces/service.ts#L50-L116)
- **`ClientModuleRegistry`**: The Node-side plugin loader and web table (`ctx.clientModules`) that scans host loaders for `dsh.client` declarations and composes the `window.__DSH_BOOT__` entry graph [packages/client/modules/src/index.ts1-49](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/modules/src/index.ts#L1-L49)

## Session Management, History Paging & Gap Repair

A `Session` encapsulates a conversation thread, maintaining a sliding in-memory window of durable events received from the host event feed [packages/client/runtime/src/client/sessions/session.ts1-146](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/session.ts#L1-L146)

### Lifecycle & Envelope Validation

1. **Opening & Validation**: Sessions originate via `session.create` or `session.resume`. The client journal validates exact V3 event envelopes using browser-safe validators before publishing follow snapshots or live entries [packages/api/session-controller/README.md27-31](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/session-controller/README.md?plain=1#L27-L31)
2. **Backwards Paging**: Paging operations include `loadOlder()` (pulls a 50-message page) and `loadThrough(seq)` (a turn-jump loader that iterates 200-message pages until the viewport covers the target sequence number) [packages/api/session-controller/README.md33-36](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/session-controller/README.md?plain=1#L33-L36)
3. **Local Submission Echoes**: `session.beginSubmission` synchronously appends an echo record to `SessionSnapshot.pendingSubmissions` prior to prompt serialization, enabling immediate UI feedback when a user submits input [packages/api/session-controller/README.md37-38](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/session-controller/README.md?plain=1#L37-L38)
4. **Gap Repair & Reconnection**: Stream disconnections trigger tail-page repair protocols using sequence IDs to reconcile missing entries without dropping application state [packages/api/session-controller/README.md33-36](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/session-controller/README.md?plain=1#L33-L36)

## Conversation Node Assembly

The `ConversationNodeAssembler` subsystem folds chronological event streams into semantic conversation structures [packages/client/runtime/src/client/sessions/conversation-assembler.ts1-50](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/conversation-assembler.ts#L1-L50)

- **Node Definitions**: Maps raw events (`user/message`, `assistant/attempt`, `tool/call`, `turn/start`) into typed `ConversationNodeDefinition` elements [packages/client/ui-conversation/src/client/conversation/assembler.ts1-200](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/ui-conversation/src/client/conversation/assembler.ts#L1-L200)
- **Incremental Folding**: Recomputes structural nodes only when new events arrive or history pages are prepended, preserving stable referential identities for UI components [packages/client/ui-conversation/src/client/conversation/assembler.ts1-200](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/ui-conversation/src/client/conversation/assembler.ts#L1-L200)
- **Turn Indexing**: Maintains turn/step tracking indexes for viewport positioning, steering targets, and scrolling indicators [packages/client/runtime/src/client/index.ts24-25](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/index.ts#L24-L25)

## Host Stream Dispatch & Multiplexing

The client runtime receives unified multiplexed streams from the host API gateway, dispatching individual frames down to corresponding session handlers [packages/client/runtime/src/client/sessions/manager.ts100-140](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/manager.ts#L100-L140)

- **Frame Routing**: `SessionManager` inspects incoming `MuxFrame` envelopes and routes data payloads to active `Session` instances based on `sessionId` headers [packages/client/runtime/src/client/sessions/manager.ts100-140](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/runtime/src/client/sessions/manager.ts#L100-L140)
- **Stream Lifecycle**: Manages SSE connection states, handles automatic retries on transport failures, and cleans up event listeners when sessions are unbound or disposed [packages/api/session-controller/README.md33-36](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/api/session-controller/README.md?plain=1#L33-L36)

## Client Module Loading & Hot Module Replacement (HMR)

The client module subsystem (`@deepseek-ai/dsh-client-modules`) bridges Node-side host plugin declarations to browser-side execution environments [packages/client/modules/src/index.ts1-24](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/modules/src/index.ts#L1-L24)

- **Boot Graph Compilation**: Scans host loader entries for `dsh.client` attributes, generating the `window.__DSH_BOOT__` entry graph (`WebBootGraph`) in module dependency order [packages/client/modules/src/index.ts1-24](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/client/modules/src/index.ts#L1-L24) [docs/subsystems/client-modules.zh.md11-22](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/subsystems/client-modules.zh.md?plain=1#L11-L22)
