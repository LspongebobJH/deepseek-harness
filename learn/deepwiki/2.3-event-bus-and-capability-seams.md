This page explains the event-driven communication model of DeepSeek Harness (`dsh`), covering session and agent events, pre-step and stream waterfalls via the Cordis plugin framework, the capability seam abstraction pattern, and the comprehensive event producer-consumer mapping.

---

## 1. Event-Driven Communication

DeepSeek Harness employs an event-driven architecture built upon the Cordis plugin framework (`vendor/cordis`). Communication between decoupled subsystems is mediated by a central event bus supporting three primary dispatch patterns: `emit` (one-to-many notifications), `parallel` (concurrent execution), and `waterfall` (sequential data transformation) [docs/event-producer-consumer.md8-9](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L8-L9)

### 1.1 Session & Agent Events

The lifecycle of an agent and its interactions are broadcast via the event bus. The `sessions` service acts as the primary coordinator for runtime state persistence and event distribution [docs/event-producer-consumer.md12-24](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L12-L24)

- **`agent/created`**: Dispatched when a new agent instance is initialized [docs/event-producer-consumer.md13](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L13-L13)
- **`agent/pre-step`**: A critical `waterfall` event where plugins (such as `agent-instructions` or `time-context`) inject contextual information into the agent's prompt boundary before LLM execution [docs/event-producer-consumer.md19](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L19-L19)
- **`agent/status`**: Broadcasts state changes in the agent loop (e.g., `idle`, `running`) [docs/event-producer-consumer.md23](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L23-L23)
- **`agent/inbox/claimed`**: Dispatched when the driver claims a message from the inbox to initiate a processing turn [docs/event-producer-consumer.md16](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L16-L16)

### 1.2 LLM & Stream Waterfalls

LLM interactions are managed via the `llm` service registry, which routes requests to provider-specific adapters (`packages/llm/llm`). Streaming responses utilize a waterfall pattern (`llm/stream`), allowing middleware components (such as token metering or reasoning extractors) to intercept and transform streaming chunks before they reach downstream consumers or UI renderers [docs/event-producer-consumer.md12-19](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L12-L19)

## 2. Capability Seams

Capability Seams are Cordis service keys that define standard interfaces for sensitive or environment-dependent operations. By injecting these seams, the core agent and tool loops remain portable across different runtime environments (e.g., local filesystems versus secure sandboxes).

### 2.1 Key Capability Seams

The following table maps key capability seams to their primary service keys, implementations, and consumers:

| Seam (Service Key) | Purpose | Primary Implementation | Key Consumers |
| --- | --- | --- | --- |
| `ctx.llm` | LLM Provider Abstraction | `llm-deepseek`, `llm-pi-ai` | `agent-loop`, `compaction-basic` |
| `ctx.fs` | Filesystem Access | `fs-local` | `tool-fs`, `agent-instructions` |
| `ctx.tools` | Tool Registry & Execution | `tools` | `agent-loop`, `subagent` |
| `ctx.agents` | Agent Registry & Lifecycle | `agent` | `apiproxy`, `acp` |
| `ctx.systemPrompt` | Prompt Assembly & Injection | `system-prompt` | `agent-loop` |

### 3.1 Data Flow: Tool Execution Seam

When an agent invokes a tool, the execution follows a structured event pipeline via the `tools` capability seam:

1. **`agent-loop`** detects tool call arguments in the streaming LLM response.
2. The `tools/pre-execute` waterfall allows security and logging hooks (such as `hooks-codex`) to inspect or intercept the invocation [docs/event-producer-consumer.md19-21](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L19-L21)
3. The registered tool implementation executes against environment seams (e.g., `ctx.fs` or `ctx.shell`).
4. The `tools/post-execute` waterfall processes results (e.g., pruning large text buffers or attaching metadata).
5. The final outcome is returned to the agent loop and committed to the durable session log as a `tool/result` event [docs/event-producer-consumer.md12-24](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/event-producer-consumer.md?plain=1#L12-L24)
