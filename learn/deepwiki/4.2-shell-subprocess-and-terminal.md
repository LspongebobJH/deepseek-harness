The Shell, Subprocess, and Terminal subsystems provide the harness with the capability to execute arbitrary code, manage process lifecycles, and maintain interactive sessions. This infrastructure is built on the **Capability Seam** pattern, allowing the agent to interact with either a local host or a remote sandboxed environment (like E2B) through a unified interface.

## 1. Overview of the Subprocess Seam & Data Flow

The `SubprocessRuntime` serves as the abstract base for all execution backends. It defines how the system resolves executables, spawns one-shot processes, and allocates persistent PTY (Pseudo-Terminal) handles.

## 2. Local Subprocess Spawning & Windows Job Objects

The `LocalSubprocessRuntime` implements execution on the host machine. It manages detached process trees and ensures that child processes do not outlive the harness.

### Process Tree Management & Windows Jobs

On Linux and macOS, the runtime uses POSIX process groups or transient user-systemd scopes (`LinuxScopeOwner`) [packages/subprocess/subprocess-local/src/linux-scope.ts182-187](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/linux-scope.ts#L182-L187) On Windows, it utilizes Job objects (`spawnCurrentTokenJobProcess` and `@deepseek-ai/dsh-win32-process bindings`) to ensure entire process trees are reaped when the parent handle closes [packages/subprocess/subprocess-local/src/spawn-runner.ts97-101](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn-runner.ts#L97-L101) [packages/subprocess/subprocess-local/src/spawn.ts113-122](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn.ts#L113-L122)

### Output Collection & Spilling

To prevent memory exhaustion while allowing agents to read large logs, the `OutputCollector` implements a tail-keep strategy:

1. **In-Memory Tail**: A bounded buffer keeps the most recent `maxBytes` of output. [packages/subprocess/subprocess-local/src/spawn.ts28-29](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn.ts#L28-L29)
2. **Spill to Disk**: If a spill cap is configured, the full stream is written to a private file under a per-process directory in the OS temp dir (created with `0700` permissions and `0600` file flags). [packages/subprocess/subprocess-local/tests/spawn-runner.spec.ts140-145](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/tests/spawn-runner.spec.ts#L140-L145)
3. **Tail Retention**: When memory limits are reached, the collector drops whole chunks from the head of its in-memory buffer while continuing to append to the spill file. [packages/subprocess/subprocess-local/src/spawn.ts28-29](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn.ts#L28-L29)

### Synchronous Host-Exit Cleanup

A critical feature of the local runtime is the `terminateForHostExit` method. The `LocalSubprocessRuntime` attaches a listener to the Node.js `exit` event to force-kill all managed process trees synchronously [packages/subprocess/subprocess-local/src/index.ts75-85](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/index.ts#L75-L85) [packages/subprocess/subprocess-local/tests/local.spec.ts110-125](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/tests/local.spec.ts#L110-L125)

## 3. Persistent PTY Sessions & Terminal Tools

While one-shot `bash` calls are stateless, the terminal session capabilities allow for interactive, stateful terminal sessions. This enables workflows like REPL exploration or multi-step debugging where environment variables and `cwd` persist.

### Implementation Details

- **Ownership**: Every PTY session is owned by a specific agent or session context. The terminal service mints opaque identifiers and restricts unauthorized tool calls.
- **Readiness Detection**: The backend uses OSC markers and shell prompt heuristics to confirm prompt readiness.
- **Linux Syscall Inspection**: The process inspector inspects `/proc` process stats and syscall states to verify if child processes are active [packages/subprocess/subprocess-local/src/spawn.ts27-28](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/subprocess/subprocess-local/src/spawn.ts#L27-L28)

## 4. E2B Cloud Sandbox Backend

The E2B backend (`subprocess-e2b`) projects remote cloud execution onto the local subprocess seam.

### Remote Environment Bootstrapping

Because E2B execution happens in a fresh VM, the harness bootstraps the environment by scrubbing parent environment secrets and serializing configurations over remote wrappers.

### Output Encoding & Remote PTY

The backend uses stream encoders and pass-through buffers to pipe binary outputs securely across the sandbox boundary, while remote PTY handlers allocate persistent pseudo-terminal instances in the remote cloud container.
