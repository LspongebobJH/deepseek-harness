## Purpose and Scope

This page details the LLM subsystem architecture in DeepSeek Harness (DSH), covering the `LlmRuntime` service seam, adapter registration, the unified `StreamChunk` protocol, error retry policies, token metering, and the concrete implementations for the DeepSeek official adapter (`@deepseek-ai/dsh-llm-deepseek`) and the multi-provider Pi.ai adapter (`@deepseek-ai/dsh-llm-pi-ai`).

## LlmRuntime & Adapter Registration

The `LlmRuntime` service acts as the central registry and dispatching hub for all large language model operations [packages/llm/llm/src/index.ts40-65](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L40-L65) It establishes a capability seam that decouples the agent loop and other plugins from specific provider network protocols.

### Key Service Methods

- **`registerAdapter(providers, adapter)`**: Mounts an `LlmAdapter` instance to specific provider route strings [packages/llm/llm/src/index.ts167-178](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L167-L178) Registration is atomic and captures the provider's retry policy [packages/llm/llm/src/index.ts170-175](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L170-L175)
- **`prepareCall(options)`**: Resolves model metadata (such as context window limits and reasoning efforts) and binds the exact adapter generation and retry policy into a one-shot executable object [packages/llm/llm/src/index.ts241-267](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L241-L267)
- **`stream(options)`**: The primary entry point for generating completions, returning an `AsyncIterable<StreamChunk>` and executing the `llm/stream` waterfall [packages/llm/llm/src/index.ts71-95](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L71-L95)
- **`listConfigurableProviders()`**: Returns the directory of providers available for configuration via settings [packages/llm/llm/src/index.ts315-325](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/index.ts#L315-L325)

### The LlmAdapter Seam

Every provider backend implements the `LlmAdapter` abstract class, which mandates metadata discovery (`listModels`), exact model resolution (`resolveModelInfo`), and the core `stream` logic yielding normalized chunks [packages/llm/llm/src/types.ts291-325](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L291-L325)

## Streaming Protocol & Chunk Assembly

DSH utilizes a unified `StreamChunk` protocol to represent all LLM outputs uniformly across providers, including text tokens, reasoning steps, tool calls, and usage telemetry.

### StreamChunk Types

- **`block-start` / `block-end`**: Demarcates the boundaries of a content block such as `text`, `reasoning`, or `tool-call` [packages/llm/llm/src/types.ts110-120](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L110-L120)
- **`text-delta`**: Contains incremental text fragments [packages/llm/llm/src/types.ts122-126](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L122-L126)
- **`reasoning-delta`**: Carries internal model reasoning increments [packages/llm/llm/src/types.ts128-132](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L128-L132)
- **`usage`**: Transmits input, output, and total token consumption metrics [packages/llm/llm/src/types.ts152-162](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L152-L162)
- **`finish`**: The terminal chunk indicating success (`stop`), length exhaustion (`length`), content filtering, or error states [packages/llm/llm/src/types.ts164-184](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/types.ts#L164-L184)

### BlockAssembler

Because raw streams arrive fragmented, the `BlockAssembler` reconstructs full `Message` objects and tracks state machine transitions during iteration [packages/llm/llm/src/assembler.ts49-65](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/assembler.ts#L49-L65)

## Implementation: DeepSeek Adapter

The `DeepSeekAdapter` targets the `deepseek-official` route using direct `fetch` calls and a custom Server-Sent Events (SSE) parser [packages/llm/llm-deepseek/README.md12-28](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm-deepseek/README.md?plain=1#L12-L28)

- **Protocol & Wire Extensions**: Communicates via OpenAI-compatible chat completions augmented with DeepSeek-specific fields for `reasoning_effort` and `thinking` mode [packages/llm/llm-deepseek/src/adapter.ts11-39](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm-deepseek/src/adapter.ts#L11-L39)
- **Image Support**: Manages image inputs via `DeepSeekFileStore`, uploading payloads through the DeepSeek Files API while gracefully falling back to inline base64 data URLs when necessary [packages/llm/llm-deepseek/README.md79-82](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm-deepseek/README.md?plain=1#L79-L82)
- **Attribution & Timeouts**: Injects `userAgent()` and session metadata headers, while protecting request execution with an `idleWatchdog` timeout guard [packages/llm/llm-deepseek/src/adapter.ts11-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm-deepseek/src/adapter.ts#L11-L32)

## Retry Policies & Error Handling

Retry operations are managed across two distinct architectural layers:

1. **Provider-Level Definition**: Captured during registration via `LlmAdapter.providerInfo()`, defining the execution strategy (e.g., `normal` mode with `maxRetries`) [packages/llm/llm/src/retry-policy.ts39-55](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/retry-policy.ts#L39-L55)
2. **Execution Middleware**: The `llm-retry` package intercepts the `llm/stream` waterfall, using `resolveRetryPolicy` to wrap stream generation in a retry loop based on the materialized configuration [packages/llm/llm/src/retry-policy.ts27-35](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/llm/llm/src/retry-policy.ts#L27-L35)
