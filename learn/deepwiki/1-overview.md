DeepSeek Harness (`dsh`) is an open-source, plugin-based agent harness developed by [DeepSeek AI](https://deepseek.com) [README.md5](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/README.md?plain=1#L5-L5) It is designed to be a flexible and extensible foundation for building, testing, and deploying LLM agents across diverse execution environments.

## Core Philosophy: Everything is a Plugin & Capability Seams

At its core, `dsh` adopts an **everything-is-a-plugin** architecture powered by a vendored version of the [Cordis](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/Cordis) framework [AGENTS.md3](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/AGENTS.md?plain=1#L3-L3) Every component—including model adapters, tool registries, session persistence, and the agent loop itself—is a plugin that can be configured, replaced, or extended [docs/architecture.md9-14](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L9-L14)

The architecture is built around **Capability Seams**, which separate functionality into three clear roles:

1. **Service Definition**: Declares the abstract interface (`ctx.llm`, `ctx.fs`, `ctx.tools`) [packages/README.md90-96](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/README.md?plain=1#L90-L96)
2. **Service Provider**: Implements the interface (`llm-deepseek`, `fs-local`) [docs/architecture.md17-27](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/architecture.md?plain=1#L17-L27)
3. **Consumer**: Consumes the capability, such as a model-facing tool (`tool-bash`, `tool-fs`) [packages/README.md90-96](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/README.md?plain=1#L90-L96)
