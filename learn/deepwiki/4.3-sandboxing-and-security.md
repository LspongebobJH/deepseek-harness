This page covers the execution environment's multi-layered sandboxing strategy, which confines subprocesses (primarily `bash` and `pwsh` executors) while providing a controlled escalation path for user-approved operations. The system is built around a unified capability seam that abstracts platform-specific enforcement mechanisms like Landlock and Bubblewrap on Linux, Seatbelt on macOS, and Restricted Tokens on Windows.

## Overview & Capability Seam

Sandboxing in dsh is a **capability** composed via the Cordis plugin framework. The core abstraction is `ctx.sandbox`, implemented by `SandboxProvider` inside `@deepseek-ai/dsh-sandbox-local`.

### Key Vocabulary

- **`SandboxMode`**: Defines the file-effect boundary. Supported modes are `read-only`, `workspace-write`, and `danger-full-access`.
- **`SandboxEnforcement`**: Indicates the backend’s enforcement completeness (`full` or `partial`).
- **Denial Signatures**: Stderr substrings utilized to detect kernel or launcher denial of file operations (`denialSignatures`).
- **Runner Failure Rules**: Rules for identifying sandbox launcher failures (e.g., missing runner binary) versus child command failures (`runnerFailureRules`).

## Linux Sandboxing: Landlock & Bubblewrap

On Linux, `LocalSandboxProvider` implements a runner chain that first attempts to confine subprocesses with `bwrap` (Bubblewrap). If unavailable—common in minimal container environments where unprivileged user namespaces are disabled—it falls back to the native `landlock-run` binary.

### `landlock-run` Native Binary

- **Location & Language**: The `landlock-run` launcher is a pure C11 program located in `native/system` that uses Linux Landlock UAPI syscalls directly.
- **Functionality**: The launcher installs Landlock rulesets (`--ro <path>`, `--rw <path>`) which are inherited through `execve` after setting `no_new_privs`.
- **Probing**: It supports a `--probe` mode to verify kernel support and exits 0 only if fully enforced.
- **Failure Semantics**: All launcher failures print a fatal line prefixed with `landlock-run:` and exit with `LAUNCHER_FAILURE_EXIT` (125) to distinguish launcher errors from child process errors.

## macOS Sandboxing: Seatbelt

On macOS, `LocalSandboxProvider` leverages the system `sandbox-exec` utility paired with dynamically generated Seatbelt profiles via `seatbeltProfileArgs`.

### Implementation Details

- **Read-Only Profile**: Denies all file writes except for literal `/dev/null`.
- **Workspace-Write Profile**: Grants recursive subpath write access (`(subpath "...")`) to the canonicalized workspace root, `/tmp`, and the OS user temp directory.
- **Probing**: Executes a functional probe running `true` under the `read-only` profile via `sandbox-exec -p`; if the kernel refuses or the binary is missing, the rung fails closed.

## Windows Sandboxing: Restricted Tokens

Windows sandboxing is implemented within the `@deepseek-ai/dsh-sandbox-windows-acl` package using **Restricted Tokens** configured with `WRITE_RESTRICTED`. This approach preserves ambient read and network capabilities but enforces a strict intersection check on write permissions.

### Implementation Details

1. **Token Derivation**: The sandbox duplicates the caller’s token with `CreateRestrictedToken`, applying flags `WRITE_RESTRICTED`, `DISABLE_MAX_PRIVILEGE`, and `LUA_TOKEN`.
2. **Capability SIDs**:
   - **Workspace SID**: Derived deterministically from the canonical workspace path using `workspaceWriteSid(path)`. Its ACE materializes once per workspace per machine lifetime as a cross-session reuse cache.
   - **Temp SID**: A distinct SID generated per live session for a private temporary directory using `tempWriteSid(path)`. Its ACE is revocable upon session end.
3. **Runner & Grants**: The `AclSandbox` class and `AclWriteGrant` manage the token lifecycle, job objects (`KILL_ON_JOB_CLOSE`), and cleanup.
4. **Fail-Closed Guarantees**: Every Win32 API interaction checks for failure and throws a `Win32Error` upon failure, preventing unrestricted spawning.

## Security Boundaries & Limitations

| Feature | Linux (Landlock/bwrap) | Windows (Restricted Token) |
| --- | --- | --- |
| **Write Restriction** | Full (or Partial on old kernels) | Partial (due to Everyone SID and hard-link behavior) |
| **Read Restriction** | Supported (enforced by Landlock rulesets) | Not supported (ambient access through normal SIDs) |
| **Network Restriction** | Not claimed in this seam | Not supported |
| **Process Visibility** | Not claimed in this seam | Not supported |
| **Console Isolation** | Supported (creates isolated consoles) | Unavailable (children share host console) |
