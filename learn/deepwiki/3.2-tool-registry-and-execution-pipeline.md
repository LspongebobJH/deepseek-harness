The `ToolRuntime` service (Cordis context key: `tools`) is the central authority for tool registration, discovery, policy enforcement, and execution within the DeepSeek Harness. It manages the lifecycle of tool calls, enforces concurrency and permission boundaries, and handles the projection of tools into the LLM context through either native function calling or Code Mode (PTC).

## 1. Tool Registration & Discovery

Tools are registered as `ToolDefinition` objects containing a model-facing name, description, JSON Schema for parameters, output definitions, and an `execute` function [packages/core/tools/README.md30-32](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L30-L32) Registration operates on scoped layers via `@deepseek-ai/dsh-scope`: root context registration makes tools globally accessible, while agent-scoped registration shadows global tools for a specific agent context [packages/core/tools/README.md79-81](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L79-L81)

### Key Registration Concepts

| Feature | Implementation Detail |
| --- | --- |
| **Shadowing** | Agent-local definitions override global definitions sharing the same name [packages/core/tools/README.md79-81](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L79-L81) |
| **Restriction** | `ctx.tools.restrict(filter)` applies allow/deny masks to narrow the visible tool set per agent [packages/core/tools/README.md79-81](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L79-L81) |
| **Schema Validation** | The registry validates JSON schemas using strict subset checks (`assertSupportedJsonSchema`) at registration time [packages/core/tools/src/index.ts23](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L23-L23) |
| **Cataloging** | The `docs/tool-catalog.md` is compiled automatically by booting plugins and reading `ctx.tools.schemas()` [docs/tool-catalog.md8-10](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/tool-catalog.md?plain=1#L8-L10) |

## 2. Execution Pipeline Waterfall

The execution pipeline processes every tool call through a structured series of interception points, separating policy enforcement, timeout wrapping, and core logic.

### The Pipeline Steps

1. **`tools/pre-execute`**: An extensible waterfall event allowing listeners (such as approval services or UI prompts) to allow, deny, ask, or cancel the call (`PreToolDecision`) [packages/core/tools/src/index.ts144-146](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L144-L146)
2. **Monotonic Guards**: Synchronous, non-bypassable checks registered via `ctx.tools.guard()` where any returned rejection reason finalizes the denial [packages/core/tools/README.md83-85](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L83-L85)
3. **`tools/execute`**: An around-dispatch waterfall wrapper handling timeouts, retries, and metrics without altering call identity [packages/core/tools/src/index.ts155-157](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L155-L157)
4. **Tool Body Dispatch**: Invocation of `ToolDefinition.execute()` with validated arguments and a guarded `AbortSignal` [packages/core/tools/README.md53-56](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L53-L56)
5. **`tools/post-execute`**: Allows inspection, value replacement, or context attachment on the successful result [packages/core/tools/src/index.ts158-185](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L158-L185)
6. **`finalizeContent`**: Definition-owned normalization of model-facing output blocks [packages/core/tools/README.md101-103](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L101-L103)
7. **`tools/result`**: An observe-only terminal event notifying subscribers of the immutable final outcome [packages/core/tools/src/index.ts180-190](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L180-L190)

## 3. Code Mode (run\_code + SDK Generation)

Code Mode allows the LLM to write a program (in TypeScript or Python) that executes tool calls programmatically rather than emitting flat JSON tool calls.

- **`run_code` Transport**: A reserved tool entry point (`RUN_CODE_NAME`) that handles execution of model-authored code blocks [packages/core/tools/src/index.ts25](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L25-L25)
- **SDK Generation**: The registry projects registered tool schemas into a type-safe SDK injected directly into the system prompt [packages/core/tools/src/index.ts26-28](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L26-L28)
- **Mode Configuration**: Controlled via `tools.mode` (`native`, `ptc`, or `both`) [packages/core/tools/README.md63-70](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/README.md?plain=1#L63-L70)

### SDK Rendering & Language Dispatch

The registry evaluates `ctx.ptcRuntime.language` against `SDK_RENDERERS` to dispatch appropriate type generators [packages/core/tools/src/index.ts33-57](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L33-L57)

## 4. Scheduling & Cooperative Cancellation

Tool concurrency and lifecycle management are governed by the execution runner context:

- **Concurrency Safety**: Declarative `isConcurrencySafe` flags determine whether a tool can execute concurrently or requires exclusive locks [packages/core/tools/src/schema.ts1-250](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/schema.ts#L1-L250)
- **Cooperative Cancellation**: Every execution passes an `AbortSignal` via `exec.signal` [packages/core/tools/src/index.ts149](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/src/index.ts#L149-L149) which must be observed by tool implementations. Pre-dispatch aborts result in `ABORTED_BEFORE_DISPATCH`, while in-flight cancellations throw or return `ABORTED` [packages/core/tools/tests/tools.spec.ts10-15](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/tests/tools.spec.ts#L10-L15)

## 5. Generated Tool Catalog Overview

The harness maintains a harvested tool catalog located at `docs/tool-catalog.md`, verified continuously by `scripts/gen-tool-catalog.ts` [docs/tool-catalog.md1-10](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/tool-catalog.md?plain=1#L1-L10) The generator boots each tool package under its default configuration against a real Cordis context to harvest exact model-visible parameters, preventing schema drift [packages/core/tools/tests/gen-tool-catalog.spec.ts25-50](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/packages/core/tools/tests/gen-tool-catalog.spec.ts#L25-L50)

Refer to [docs/tool-catalog.md](https://github.com/deepseek-ai/deepseek-harness/blob/ddefc45f/docs/tool-catalog.md?plain=1) for the complete, machine-verified enumeration of shipped tool packages, model-visible names, requirements, and side-effects.
